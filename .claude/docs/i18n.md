# Internationalisation

i18n is in place from the first screen, not retrofitted. There is no phase in this project
where hardcoded strings are acceptable.

## Stack

- `i18next` — the core
- `react-i18next` — the `useTranslation` hook
- `expo-localization` — device locale and region detection
- `Intl` — dates, numbers and relative time. No date formatting library.

## Supported locales

Declared in `frontend/apps/mobile/src/shared/config/locales.ts`.

| Code | Language | Status   |
| ---- | -------- | -------- |
| `en` | English  | fallback |
| `ru` | Russian  | full     |

Adding a locale means adding the code to `LOCALE`, creating the folder under
`shared/i18n/locales/<code>/`, and nothing else. If a key is missing there, i18next falls
back to `en`.

## Namespaces

One namespace per domain, mirroring the screens. A component loads only the namespace it
needs so bundles stay legible.

| Namespace    | Covers                                                   |
| ------------ | -------------------------------------------------------- |
| `common`     | Buttons, generic labels, confirmations reused everywhere |
| `navigation` | Tab titles, screen headers                               |
| `deck`       | Deck list, deck detail, deck editing                     |
| `study`      | The review screen, rating buttons, session summary       |
| `generation` | The AI wizard, its stages, the preview screen            |
| `profile`    | Stats, streaks, settings                                 |
| `errors`     | Every user-visible error message                         |

`en` is the source of truth. When you add a key, add it to **both** `en` and `ru` in the same
change. A key that exists in only one locale is a bug.

## Key naming

Keys are `camelCase`, nested at most two levels, grouped by the UI region they appear in.

```json
{
  "card": {
    "dueCount_one": "{{count}} card due",
    "dueCount_other": "{{count}} cards due",
    "lastStudied": "Last studied {{date}}"
  },
  "actions": {
    "study": "Study",
    "edit": "Edit"
  },
  "empty": {
    "title": "No decks yet",
    "description": "Create your first deck to get started"
  }
}
```

Name a key after **what it means**, not what it says. `actions.delete`, never
`areYouSureYouWantToDelete`. The English text can change without touching any component.

## Usage

```tsx
const { t } = useTranslation('deck');

t('actions.study');
t('card.dueCount', { count: dueCount });
t('common:actions.cancel');
```

- Load the namespace the component belongs to; reach into another with the `ns:key` prefix.
- Never concatenate translated fragments. A sentence is one key with interpolation, because
  word order differs between languages.
- Never nest a `t()` result inside another `t()` call.

## Typed keys

`resources.ts` augments the i18next module so that `t()` autocompletes and a wrong key is a
type error:

```ts
declare module 'i18next' {
  interface CustomTypeOptions {
    defaultNS: 'common';
    resources: typeof resources;
  }
}
```

This is the mechanism that makes rule 5 in `CLAUDE.md` enforceable. Do not weaken it.

## Plurals

Use i18next's suffix form, never a manual ternary. English needs `_one` and `_other`;
Russian needs `_one`, `_few`, `_many` and `_other`. This is exactly why plural logic does
not belong in components.

```json
{
  "dueCount_one": "{{count}} карточка",
  "dueCount_few": "{{count}} карточки",
  "dueCount_many": "{{count}} карточек",
  "dueCount_other": "{{count}} карточки"
}
```

## Formatting

Dates, numbers and relative times go through helpers in `shared/lib/format`, which wrap
`Intl.DateTimeFormat`, `Intl.NumberFormat` and `Intl.RelativeTimeFormat` with the active
locale. Never format a date by string concatenation, and never hardcode a separator.

Review intervals shown on the rating buttons ("2d", "3mo") are formatted through the same
helpers, because those abbreviations are translated too.

## Locale resolution

1. If the user picked a locale in settings, use it. It is persisted in MMKV through the
   settings store.
2. Otherwise take the first device locale from `expo-localization` that appears in `LOCALE`.
3. Otherwise fall back to `en`.

Changing the locale at runtime calls `i18n.changeLanguage` and re-renders; it never requires
an app restart.

## Content language vs interface language

These are separate settings and must not be conflated.

- **Interface language** is what this document covers.
- **Content language** is what the AI generates cards in. It is sent as `language` in the
  generation request and defaults to the interface locale, but the user can override it —
  someone with a Russian interface will often want English cards.
